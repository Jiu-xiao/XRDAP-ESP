# 给 libxr 会话的需求(来自 ESP32-S3 XR-DAP 上板验证会话,基于 libxr-c 52fa2e92)

数据细节:`D:\Codex\tmp\rml\results-20261016.md`、`D:\Codex\tmp\xrdap-s3\libxr-issues-20261016.md`。
我没有改 libxr-c;性能实验用的是插桩副本 `D:\Codex\tmp\xrdap-s3\libxr-trace`(从 52fa2e92 复制,带 `g_dap_trace`)。

## 一、需要修的 bug(52fa2e92,与执行模式无关)
1. **开机后第一条主机命令得不到应答**。复位后任意 WinUSB 客户端(我的 Python 客户端、OpenOCD)的第一个会话的第一条命令超时,等 30 秒也一样;之后的会话从第一条命令起正常。e196f094 上没有。复现:复位,先发 DAP_Info,读超时;再发一次就好。
2. **同步客户端先写 4 个请求再读,设备死锁,要硬复位**。复现:`NPAIR=2 python xrblock_usb.py 10000000`(补零或不补零都一样),或 `xrusb_ceiling2.py` 的深度 4。2、3 个在飞没事;重叠 I/O 客户端 4/6/8 个在飞没事。e196f094 上 4 个同步写能过。怀疑:窗口计数让第 4 个 OUT 要等有响应被取走才能收,而主机阻塞在这个写里。pyOCD 风格的客户端(写满 packet_count 个包再读)可能受影响,我没测。

## 二、性能需求(已用插桩副本验证因果)
3. **命令池槽数 = 窗口(4)**。现在 2 个槽:大写命令执行时,后面的小 TAR 命令占着第二个槽,下一个大写命令没有槽可接收(trace 里 ARM_OUT 原因 4),接收和执行相加而不是重叠。改成 4 个槽:TAR 加块写 4 个在飞 332 → 565 KiB/s。
4. **两步接收让纯 OUT 吞吐减半**。命令先收一个 64 字节包再按长度请求剩余部分:纯 OUT(1016 字节请求,不做 SWD)490 KiB/s,a1d233ec(整包接收)是 985。第一次接收改成整包:777。3 和 4 都做:TAR 加块写 783 KiB/s,连续块写 788(ISR 旧版 434 / 775)。两步接收是为了结束"长度恰为 64 整数倍"的命令,整包接收会把这个问题重新打开,替代方案需要同时保证两者(例如 SOF 时检查已收字节是否已构成完整命令,构成就结束这次传输)。
5. **Step() 线程要和 USB 中断分核**(文档要求,并列入示例)。同核:小命令慢 6%~15%、低频块读 289 → 183 KiB/s、尾部延迟最差(最大 1970 µs);分核(USB 在 core 0,SWD 引脚和 Step 在 core 1):慢 1%~3%,OpenOCD 12 MHz 读 637~643(ISR 旧版 578)。ESP32-S3 的专用 GPIO 必须在运行 Step() 的核上创建。

## 三、设计请求(待你们定)
6. **DAP 类末尾加模板参数 `DapExecution Execution = THREAD`(`THREAD` / `INLINE`)**:池不动(命令池、响应池两种模式相同);`INLINE` 在 owner 上下文里(通常是 USB 中断)执行普通命令;延时类命令(DAP_Delay、ResetTarget、带等待的 SWJ_Pins,以及包含它们的批)交给 `Step()` 线程睡,不再用 Timer 和 `pending_action_`(INLINE 因此也需要一个 Step 线程,但只处理这些命令);命令顺序要严格保持。注意:INLINE 下命令池槽数多于 2 个没有用,因为中断忙于执行时无法重新武装 OUT(a1d233ec 上命令缓冲 2→4 无改善,写 434 不变),文档要写明。
7. **`LIBXR_SINGLE_CORE` 只管对齐,不负责放核**,libxr 里没有核亲和性接口。是否给 `Thread::Create` 加可选亲和性参数,或让 BSP 的 USB 设备暴露中断所在的核,需要你们定。
8. **SwdGeneralGPIO 写传输比读传输贵 35%**(12 MHz 请求:4.4 µs 对 3.26 µs):每个数据位 3 次 GPIO 写(数据、时钟低、时钟高),读是 2 次写加 1 次读;把数据变化和时钟下降沿合并成一次写即可(手写引擎已验证,写 703 对读 761 周期)。采样点现状(时钟上升沿前读)是对的,不要改。
9. **文档提示**:裸线上默认驱动强度的振铃会引起 SWD 错误(我们 SWCLK/SWDIO 降一档到 cap 1 后 2/4/12 MHz 烧录 64/64 通过,RMLink 同样降一档后才能在 4 MHz 以上工作)。驱动强度保持在 BSP,libxr 本体不动;SWDIO 设为输出后要等约 16 个 CPU 周期才生效(APB 寄存器写),快速 bit-bang 驱动要注意。

## 四、我已验证通过的(52fa2e92,供你们对照)
补零请求加重叠客户端 4/6/8 个在飞不卡;OpenOCD 烧录 4 MHz 8/8、12 MHz 16/16;probe-rs 基准能跑;单类设备绑定 WinUSB(问题代码 0,服务 WINUSB);客户端超过 4 个在途不致命。
