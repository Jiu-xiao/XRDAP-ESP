# ESP32-S2 跳拍与缺帧：当前方案、证据和清理结论

日期：2026-10-26。适用范围：本仓库的 S2 正常 USB DAP+CDC+Wi-Fi 固件；比较 S3-Lite 的代码与链接策略。

## 当前结论

S2 高速 SWD 档位的 Flash 取指开销与单核上的在线状态查询共同压缩了 1 ms 采样余量。当前候选 `0.5.5-preview-s2-fast16-iram-r1` 在 USB、请求 4 MHz、a+b、1 ms、Wi-Fi 已连接的四轮 30 秒对照中，共 120025 帧，跳拍、CSV 缺口、缓冲丢帧、失败值和每轮 SWD 错误均为 0。其中两轮各执行 59 次额外 DHCSR 查询。用户GUI仍报告4MHz偶发缺口、1MHz约0.1%缺口，严格GUI验收未通过；不将原始命令短测推广为GUI、长期或所有时钟配置的保证。

源代码：父仓库 `c916d0a`，Core `be2c067`，LibXR `5d795f21`。当前镜像为基于 `0680575` 加上现已提交到 `c916d0a` 的代码构建，版本后缀独立标识；精确镜像身份见下文。

## 任务契约与执行边界

目标：解决 S2 在原 GUI/CLI 的双变量 1 ms 采样中明显高于 S3-Lite 的跳拍，并从 `d6d812d`（含）审查冗余代码。范围：S2 缓存、SWD/MEM-AP 热路径、相关诊断和测试，以及历史改动的消融审查。保留协议、帧布局、变量地址、引脚、目标运行状态与真实漏拍账目。

用户已授权配合网页刷写和及时 git commit。只在本地提交，不推送或发布。试验期间不向 STM32 发复位、暂停、继续运行或目标内存写命令；正常 SWD 连接仍会配置调试端口。每次先核对实际设备版本、热点和目标状态，再独占对应 DAP 连接；GUI 活跃时只用独立 CDC 读取诊断。

执行平面是 Windows/ESP-IDF 5.5.2，Xtensa GCC 14.2.0，主机回归使用 WSL Linux。xrobot/libxr CLI 不在 PATH，本任务不使用代码生成器，未安装或更改工具版本。既有未跟踪文档、技能和工具均保留；tools 不进入提交。

## 定位依据与修正

- 原 r2 的同环境 USB 对照，在请求 4 MHz 下每轮 30 秒的跳拍和 CSV 缺口为 `240/227/220`，缓冲丢帧和失败值为 0。因此这批缺口首先来自漏采，而不是已经生成的帧在传输中消失。
- 基线 S2 的指令缓存为 8 KB，12 个高速 SWD 档位都在 Flash，单档 3452–9488 字节。S3 的热路径和一个高速档原本进入 IRAM，且有两个核。不能把 S3 的时序余量直接套在 S2 上。
- `find.md` 中用 SWJ 测速推断 `min_half_≈98`、2 MHz 已进入汇编路径不成立。`Calibrate()` 将 `min_half_` 限制为至多 60，240 MHz CPU 下请求 2 MHz 必然仍走 paced。SWJ 序列的循环开销不能代表 DAP 事务选档。
- 已通过设备 CDC 观测确认：本轮请求 4 MHz 时选中 `index=11`，即 `N=16`。当前 ELF 中它在 IRAM 地址 `0x400277e0`，大小 9488 字节。这是实际选档与链接证据，不是由请求频率猜档。
- 同一主机 EXE 的 GUI 与 CLI 输入不同：GUI 每 500 ms 自动用 vendor READ 读 DHCSR，且取帧间隔最多 20 ms。CLI 纯 watch 没有该额外 SWD 查询。两者 EXE SHA256 同为 `3e204229…`。

## 已采用的改动与各阶段结果

1. S2 指令缓存从 8 KB 增至 16 KB，少 8192 字节堆。构建时显式更新已有 sdkconfig 的 choice；仅修改 defaults 不会覆盖旧构建配置。该单因素候选在 1/4 MHz 各三轮 30 秒均为零缺口，但加入清理后的重复测试仍有偶发缺口，GUI 也未通过。
2. S2 将共享 `mem_ap` 对象置 IRAM，IRAM text 增加 6396 字节，DRAM data 增加 12 字节。在线读取与采样共用这一段代码。它减少了额外状态查询造成的漏拍，但仍不足以消除 GUI 缺口。
3. S2 仅将常用 `Xfer<16>` 特化置 IRAM，再增加约 9492 字节 IRAM text。其余档位保留原位置，S3 原 N=10 策略保持。当前 IRAM text 69156 字节，联网板测最低堆 79404 字节。
4. 增加只在设置时钟时写入的 32 位 `last_fast_level` 诊断，CDC heap 可读。它用于核实当前性能试验命中了哪一个高速档，不在每帧/每笔 SWD 事务中更新。字段表示最近一次高速选档，paced 模式不会更新它，不能用来判断当前低速路径。

| 场景 | 原 r2 | cache16+清理 | 再加 MEM-AP IRAM | 再加 N16 IRAM |
|---|---|---|---|---|
| 普通 CLI，4 MHz，30s×3，跳拍/缺口 | 240/227/220 | 0/1/0 | 未重复此组 | 见下方同输入组 |
| 20ms取帧，纯采样，30s×2 | 未测 | 1/0 | 1/1 | 0/0 |
| 同上+500ms DHCSR查询，30s×2 | 未测 | 8/13 | 1/6 | 0/0 |
| 用户 GUI | 原始问题 | 25258帧时23缺口 | 78.22s、78194帧、17缺口 | 用户报告4M偶发、1M约0.1% |

表中“跳拍/缺口”均核对探针统计与 CSV，不用显示帧率代替。前一版 1 MHz 三轮亦有 `0/1/0`；当前高速档改动的主验收是请求 4 MHz，尚未重做全部低速组合。

## 从 d6d812d 起的消融与清理

| 部分 | 决定与具体消费者 |
|---|---|
| AP选择、TxnOk读取更新后的ACK | 保留：多AP与错误判定正确性，恢复回归测试 |
| SWD重新进入、清sticky、重读CSW、恢复限频 | 保留：链路失步后的恢复；不重放失败目标读取 |
| socket发送超时、EINTR和会话结束 | 保留：对端不读回复时有界退出，socket回归 |
| S2采样优先级24、paced IRAM、批量字读取、元数据只读命令让路策略 | 保留：既有A/B与功能回归；保证同核命令仍能响应 |
| 自由计数GPTimer、绝对deadline、elapsed_ticks | 保留：长中断延迟时不低报真实漏拍，merged=0不是无用证明 |
| 一次性唤醒deadline | 保留：长帧期间避免信号量重复累计 |
| wake延迟与fairness busy分离 | 保留：避免把已给其他任务的时间重复算为采样占用 |
| batch_hits字段、初始化、每批原子增量及CDC输出 | 已删除：只服务旧批读实验；测试改为直接检查8种场景的TAR写次数、值和失败位图 |
| 早期“S2没有RAM容纳任何高速档”等注释 | 已修正：当前按实际链接和板上堆余量说明成本 |

现阶段保留 cache16、MEM-AP IRAM 和一个高速档 IRAM 的已测组合。各项单因素改善有记录；最新组合下继续消融前两项、回收更多 RAM 尚未做，不据早期独立收益宣称最终组合已经最小化。

## 兼容性与验证边界

DAP/vendor v2、帧布局、采样缓冲4096字节、错误/取消语义、会话所有权、引脚、ISR职责和真实跳拍账目保持。停止不补做过期帧，不伪造连续序号。批读仍按1KiB TAR边界拆分，失败读取不重放。Core统计结构移除了实验字段，源码消费者须重新编译；无线协议不含该字段。CDC文本增加实际选档诊断，已有本地key=value解析器可读取其余字段。

当前L7证据限于上述硬件和短测输入。GUI最后一轮、TCP同配置、其他SWD频率、30分钟长稳和独立评审分别记录，不用CLI成功替代。严格条件是跳拍、实际CSV缺口、缓冲丢帧、失败值和SWD错误均为0。发生NO_ACK/失败值/掉线/资源不足即停，不复位目标来掩盖问题。
