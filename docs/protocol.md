# XR-DAP 链路帧与 XR 厂商扩展

本文说明 XRDAP-ESP32-S3 在串口和 TCP 上传输 CMSIS-DAP 包时使用的帧格式，以及探针实现的 XR 厂商扩展命令（0x80 到 0x85）。USB 上的 DAP 包按 CMSIS-DAP v2 的 Bulk 端点收发，没有额外的帧。

所有整数都是小端。十六进制示例中的空格只为易读。

## 1. 串口帧

串口使用 libxr 的 Topic 打包帧，固件端由 libxr 的 `DapSerialTransport`（`src/driver/debug/dap_serial_transport.hpp`）实现，电脑端由 `host/xrdap-forward` 实现。

```
prefix 0x5A(1) + data_len(3) + topic_crc32(4) + timestamp_us(6) + version(1) + header_crc8(1) + payload(data_len) + crc8(1)
```

| 字段 | 内容 |
|---|---|
| prefix | 固定 `0x5A` |
| data_len | payload 的字节数，24 位 |
| topic_crc32 | topic 名的 CRC32。请求 topic 为 `dap_req`（`0xDC8309C5`），响应 topic 为 `dap_resp`（`0x89E1A688`） |
| timestamp_us | 48 位。探针在响应里填自己的微秒时间；请求填 0，探针不读取 |
| version | 固定 `0x01` |
| header_crc8 | 前 15 字节的 CRC8 |
| payload | `n(2) + DAP 包(n)`，n 为 DAP 包的字节数，不补零 |
| crc8 | 帧头和 payload 的 CRC8 |

CRC8 为反射多项式 `0x8C`、初值 `0xFF`；CRC32 为反射多项式 `0xEDB88320`、初值 `0xFFFFFFFF`、结果不取反（`"123456789"` 的值为 `0x340BC6D9`）。

例：请求 `DAP_Info(0xFF)`（查询包长，DAP 包为 `00 FF`）的完整帧：

```
5A 04 00 00 C5 09 83 DC 00 00 00 00 00 00 01 B1 02 00 00 FF 32
```

探针按以下规则解析：

- 帧头 CRC8 错、version 不是 1、topic 不是 `dap_req`、data_len 小于 2 或大于 2 + 1024 时，丢弃当前候选帧，从缓冲里的下一个 `0x5A` 重新开始解析。
- 尾 CRC8 错时同样丢弃并重新同步。
- n 大于 1024 或 n + 2 大于 data_len 时丢弃该帧，不回响应。
- 被丢弃的请求没有响应，由上位机超时重发。xrdap-forward 等待 2 秒（`--timeout-ms`），超时后向 OpenOCD 回一个字节 `0xFF`。

请求和响应一一对应。上位机每次发一个请求，收到响应后再发下一个。没有响应内容的命令，响应帧的 n 为 0。

固件的波特率为 4 000 000（`firmware/main/config.hpp` 的 `kSerialBaud`），8 位数据、无校验、1 位停止位、无流控。

串口没有连接和断开的概念，探针据此对串口发起的采样做了单独处理，见 3.5 节。

## 2. TCP 帧

探针的 TCP 3241 端口和 xrdap-forward 的监听端口使用同一种帧，与 OpenOCD 的 `cmsis-dap backend tcp` 一致：

```
"DAP\0"(4) + 长度(2) + 类型(1) + 保留(1) + DAP 包
```

类型为 1 表示请求，2 表示响应；保留字节填 0。长度是后面 DAP 包的字节数。

- 同一时间只服务一个客户端，请求按顺序执行并应答。
- 探针收到的帧头无效（magic 不对、类型不是 1、长度为 0 或大于 1024）时关闭连接。
- 没有响应内容的命令（例如 `DAP_TransferAbort`）不回 TCP 帧。
- xrdap-forward 把 TCP 帧去掉 8 字节头后换成串口帧发给探针，响应反向转换，不解析 DAP 内容。客户端断开后，它向探针发送一次 `84 00`（停止采样）。

## USB 主机的注意事项

USB 全速的 Bulk 包是 64 字节。请求长度正好是 64 的整数倍（128、192 字节等）、又小于 DAP 包长时，OUT 传输没有短包来标志结束，探针会一直等下去，表现是这个请求没有响应、之后的响应还会错位。主机发完这样的请求后要再发一个零长度包。8 个条目的 SUB_SET 正好 128 字节，最容易遇到。`xrdap` 已经处理；自己用 libusb、pyusb 写客户端时要加。接收时 IN 请求的长度要取端点最大包长的整数倍（不小于 DAP 包长）。

## 3. XR 厂商扩展

### 3.1 规则

- 命令放在 CMSIS-DAP 的厂商命令区 0x80 到 0x85，USB、TCP、串口使用同一种包。
- 探针不支持的命令响应只有一个字节 `0xFF`，这是 CMSIS-DAP 的标准行为。上位机发送 INFO 得到 `FF` 时，即可判断探针没有实现扩展。
- 只支持 SWD。目标按小端处理，数值就是目标内存里的原始字节。
- 变量地址由上位机解析（符号表、DWARF），探针只处理地址。
- 使用扩展命令前，上位机要先用 `DAP_Connect` 以 SWD 方式连接（port 为 0 或 1），并确认目标可访问。探针不替上位机连接；还没有连接时，READ、WRITE、SUB_SET 和开始采样都返回 0x04。`DAP_Disconnect`、TCP 客户端连接或断开、采样因传输断开而自动停止之后，都要重新 `DAP_Connect`。
- 用过 READ、WRITE 或采样之后，上位机必须把 DP SELECT、AP CSW、TAR 当作未知，重新写入。OpenOCD 会缓存这些寄存器，所以扩展命令和 OpenOCD 不在同一个连接里混用。

采样期间探针被订阅独占：

- 从开始采样到停止，只接受 `DAP_Info`（0x00）、`DAP_HostStatus`（0x01）和 0x80 到 0x85。其他命令一律只回一个字节 `0xFF`，不执行。
- READ、WRITE 在采样期间可以使用，它们和采样任务轮流占用 SWD，可能使采样出现跳拍。
- 采样在以下情况停止：

| 情况 | 停止的采样 |
|---|---|
| 收到 SUB_CTRL 停止（`84 00`） | 任何传输发起的采样 |
| USB 总线复位（拔出或主机复位） | USB 发起的采样 |
| TCP 客户端断开 | 任何传输发起的采样 |
| 新的 TCP 客户端连接 | 任何传输发起的采样 |
| 5 秒内没有收到任何串口请求 | 串口发起的采样 |

串口发起采样后，上位机要至少每 5 秒发一个请求（SUB_READ 即可）。自动停止后缓冲里的帧保留，仍可以用 SUB_READ 读走，直到下一次 SUB_SET。

### 3.2 请求、响应和状态

请求为 `命令字节 + 参数`；响应为 `命令字节 + 整体状态 + 数据`，命令字节原样回显。整体状态不为 0 时响应只有这两个字节，SUB_SET 因资源不足返回的 0x03 除外（见 3.4 节）。

请求长度与命令里的计数字段对不上时返回 0x01，不执行。READ、WRITE 在执行前先计算响应大小，放不进一个 DAP 包（1024 字节）时返回 0x03，不执行。

| 整体状态 | 含义 |
|---|---|
| 0x00 | 成功；各条目的结果看条目状态 |
| 0x01 | 参数非法：长度对不上、计数为 0、size 不是 1/2/4/8、解引用次数大于 8、period 为 0、div 为 0 或 phase ≥ div、flags 保留位非 0、SUB_CTRL 的 op 未定义 |
| 0x02 | 状态不允许：采样中发 SUB_SET 或再次开始；没有成功的 SUB_SET 就开始或读取；SWD 链路 2 秒内没有空出来 |
| 0x03 | 资源不足：条目数超过 32、响应放不进一个包、一次订阅用到超过 8 个不同的 AP、估计的单帧耗时大于周期 |
| 0x04 | 没有连接目标：还没有 `DAP_Connect`，或读取 AP 的 CSW 失败 |

条目状态（READ、WRITE 的每个条目一个字节；采样帧里只用 1 位表示成功或失败）：

| 条目状态 | 含义 |
|---|---|
| 0x00 | 成功 |
| 0x10 + k | 第 k 级（0 到 7）读指针时 SWD 返回 FAULT 或超时 |
| 0x1F | 最后一次读或写时 SWD 失败（包括写后检查到粘滞错误） |
| 0x20 + k | 第 k 级的读地址没有 4 字节对齐 |
| 0x2F | 最后访问的地址没有按 size 对齐（size 为 8 时要求 4 字节对齐） |
| 0x30 + k | 第 k 级读出的指针为 0，不再继续 |

### 3.3 条目

一个条目描述一个变量的位置，可以经过最多 8 级指针。

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0 | 1 | ap：MEM-AP 编号 |
| 1 | 2 | id：上位机自定，响应里原样带回 |
| 3 | 1 | size：1、2、4 或 8 |
| 4 | 4 | base：起始地址 |
| 8 | 1 | n：解引用次数，0 到 8 |
| 9 | 2×n | deref_off[i]，i16，i = 0 到 n-1 |
| 9+2n | 2 | final_off，i16 |

条目长度为 11 + 2n 字节。WRITE 的条目后面紧跟 size 字节的值；采样条目后面紧跟 `div(2)` 和 `phase(2)`；READ 的条目没有额外字段。

探针按以下步骤求出最终地址：

```
cur = base
for i in 0..n-1:
    addr = cur + sign_extend(deref_off[i])      // 32 位回绕
    addr 不是 4 的倍数     -> 条目状态 0x20+i，结束
    p = read32(addr)                             // SWD 失败 -> 0x10+i，结束
    p == 0                 -> 条目状态 0x30+i，结束
    cur = p
addr = cur + sign_extend(final_off)
addr 不是 size 的倍数（size 为 8 时按 4） -> 0x2F，结束
读或写 size 字节                                  // SWD 失败 -> 0x1F
```

n 为 0 时直接访问 `base + final_off`。base 为 0 是合法的（Cortex-M 的 0 地址有效），只有读出来的指针为 0 才算空指针。数组下标和链表遍历由上位机展开成多个条目。

### 3.4 命令

#### 0x80 INFO

请求：`80`

响应固定 26 字节：

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0 | 1 | 0x80 |
| 1 | 1 | 整体状态 |
| 2 | 1 | 协议版本，当前为 1 |
| 3 | 4 | 功能位：bit0 READ，bit1 WRITE，bit2 采样，bit3 8 字节访问；本固件为 0x0F |
| 7 | 2 | 一个请求或订阅最多的条目数：32 |
| 9 | 1 | 最大解引用深度：8 |
| 10 | 4 | 环形缓冲字节数：16384 |
| 14 | 8 | 探针当前时间，µs |
| 22 | 4 | 一次 SWD 访问（写 TAR 加读一个 AP 寄存器）的标定耗时，µs |

偏移 22 的值在每次 SUB_SET 时按当前 SWD 时钟重新标定：探针连续 16 次写 TAR 并读 CSW，取平均值。这与直接读一个字（n 为 0）的 SWD 事务数相同，不访问目标内存。开机后还没有 SUB_SET 时为 0。

#### 0x81 READ

请求：`81 count(1) item…`，count 为 1 到 32。

响应：`81 状态 count(1)`，然后每个条目 `id(2) 条目状态(1) value(size)`。失败的条目 value 全为 0。

#### 0x82 WRITE

请求：`82 count(1) (item value)…`，value 为 size 字节，按目标字节序。

响应：`82 状态 count(1)`，然后每个条目 `id(2) 条目状态(1)`。

条目按顺序执行，已经写入的不回滚，某个条目失败不影响后面的条目。8 字节写是两次 32 位写，不是原子的。

#### 0x83 SUB_SET

请求：`83 period_us(4) flags(1) count(2) (item div(2) phase(2))…`

- period_us：基础周期。
- flags：bit0 为 0 时缓冲满后覆盖最旧的帧，为 1 时停止写入新帧；其余位必须为 0。
- count：1 到 32。

响应：`83 状态 max_frame_bytes(2) est_frame_us(4)`

- max_frame_bytes：所有条目都到期时一帧的字节数。
- est_frame_us：估计的单帧耗时。

SUB_SET 只能在采样停止时发送，否则返回 `83 02`。还没有 `DAP_Connect` 时返回 `83 04`。

参数检查通过后，探针按当前 SWD 时钟实测：先标定 INFO 偏移 22 的单次访问耗时，先读好各 AP 的 CSW，再把全部条目按采样时的访问顺序试读一遍，耗时记为 T（不含读 CSW）。试读访问的地址与采样相同，副作用也相同。

```
est_frame_us = 10 + 1.6 × T        （整数运算：10 + T × 8 / 5）
```

系数 1.6 来自实测：采样期间，同一个核上的 DAP 线程还要处理 SUB_READ，会抢占采样任务。8 个条目、T 约 265 µs 时，每帧实际耗时约为 T 的 1.5 倍。

est_frame_us 大于 period_us 时返回 0x03，响应里照样填写 max_frame_bytes 和 est_frame_us，上位机可以据此选一个可用的周期。这时配置不生效，之前的配置和缓冲保持不变。成功时清空缓冲和计数器。

估计值只用于拒绝明显跟不上的配置，实际情况以 SUB_READ 返回的跳过节拍数为准。

#### 0x84 SUB_CTRL

请求：`84 op(1)`；op 为 0 停止，1 开始，2 清空缓冲和计数器。

响应：`84 状态`

- 开始：节拍序号从 0 开始，计数器清零，各 AP 的 CSW 在此时读一次。已经在运行或没有成功的 SUB_SET 返回 0x02；没有 `DAP_Connect` 或读 CSW 失败返回 0x04。
- 停止：没有在运行时也返回 0x00。缓冲里的帧可以继续用 SUB_READ 读走。

#### 0x85 SUB_READ

请求：`85 max_bytes(2)`

响应头 24 字节，后面是帧：

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0 | 1 | 0x85 |
| 1 | 1 | 整体状态 |
| 2 | 8 | 探针当前时间，µs |
| 10 | 4 | 缓冲里剩余未取的帧字节数 |
| 14 | 4 | 累计缓冲丢帧数 |
| 18 | 4 | 累计跳过节拍数 |
| 22 | 2 | 本次返回的帧数 |
| 24 | … | 帧 |

只返回完整的帧，帧的总长不超过 `min(max_bytes, 1024 - 24)`；缓冲为空时帧数为 0。从没有成功的 SUB_SET 时返回 0x02。两个计数器在 SUB_SET 成功、开始采样和 op 2 时清零。

### 3.5 采样

#### 周期与分频

- 节拍序号 k 从 0 开始，第 k 拍的目标时刻为开始时刻 + k × period_us，不累计漂移。
- 条目在 `(k + phase) % div == 0` 的拍被采样。div 为 1 表示每拍都采；phase 用来错开慢速条目。一拍里到期的条目按 SUB_SET 中的顺序依次读取。
- 没有条目到期的拍不产生帧。
- 距离下一拍超过 3 ms 时采样任务休眠，其余时间在 SWD 所在的核上忙等，以保证节拍精度。

#### 帧格式

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0 | 4 | 节拍序号 k |
| 4 | 6 | 时间戳，µs，在该拍开始读取前取得 |
| 10 | ceil(m/8) | 状态位图，m 为到期条目数；第 i 个到期条目对应第 i 位（低位在前），1 表示失败 |
| … | … | 各到期条目的值，按到期顺序，每个 size 字节，失败时全为 0 |

到期的条目由 k 和各条目的 div、phase 推算，帧里不重复列出。

- 时间戳取自 `esp_timer_get_time`，是探针的单调微秒时间，48 位。每次开始采样时时间轴不重置，节拍序号从 0 重新计；探针重启后时间轴从 0 开始。
- 一帧内的条目依次读取，同一帧的变量之间有时间差，不是同一时刻的值。
- 对齐到上位机时钟：记下 INFO 或 SUB_READ 请求前后的本机时间，取中点与响应里的探针当前时间配对，得到偏移量，误差约为半个往返时间。每次 SUB_READ 都可以顺便更新偏移量。

#### SWD 来不及

一拍的实际耗时超过周期时，探针不补做，直接跳到下一个还没过去的节拍。节拍序号因此出现缺口，缺的拍数累计到跳过节拍数。探针不会自动降频或去掉条目，由上位机根据计数器调整。

#### 读取太慢

帧先写进 16384 字节的环形缓冲（每帧另占 2 字节长度）。缓冲满时按 flags.bit0 覆盖最旧的帧或丢弃新帧，覆盖或丢弃的帧数累计到缓冲丢帧数，节拍序号的缺口也能看出丢了哪几拍。剩余未取字节数不为 0 时，上位机应立即再读。

每拍的字节数为 10 + 位图 + 各到期条目的 size，按 div 折算平均值后与链路的实际速度比较，即可估计带宽是否够用。

| 计数器 | 原因 | 处理 |
|---|---|---|
| 跳过节拍数 | SWD 来不及 | 增大周期、增加分频、减少条目 |
| 缓冲丢帧数 | 读得太慢或链路带宽不足 | 读得更勤、增加分频、减少条目 |

### 3.6 SWD 访问

- DP SELECT：访问 MEM-AP 时写 `ap << 24`。CSW、TAR、DRW 都在 bank 0。
- CSW：每个 READ、WRITE 命令中第一次用到某个 AP 时、SUB_SET 试读时以及开始采样时，读一次该 AP 的 CSW。访问时写入 `(原值 & ~0x37) | Size`，即清掉 Size（位 2:0）和 AddrInc（位 5:4），保留 Prot、HNONSEC 等其余位，设置访问宽度并关闭自增。同一命令或同一次采样期间不重新读取。
- 读一个字：写 TAR，读 DRW，再读 DP RDBUFF 得到结果。条目按顺序逐个访问。
- 写一个字：写 TAR，写 DRW，再读 DP CTRL/STAT，检查 STICKYORUN、STICKYERR、WDATAERR。
- 1、2 字节访问：CSW 的 Size 设为 8 位或 16 位，值在 DRW 中由地址低位决定的字节通道上，探针把它放到 value 的低字节。
- 8 字节：两次 32 位访问，低地址在前，不是原子的，目标运行时可能读到前后不一致的值。4 字节及以下的对齐访问是单次访问。
- WAIT 应答：沿用 `DAP_TransferConfigure` 设置的重试次数，超过算失败。
- 任何访问出现 FAULT、超时或粘滞错误后，写 DP ABORT = `0x0000001E`（STKCMPCLR、STKERRCLR、WDERRCLR、ORUNERRCLR），再继续下一个条目。
- 读写内存由 MEM-AP 完成，不需要停核。

### 3.7 字节示例

以下数值仅作示例。

#### INFO

请求：`80`

响应：`80 00 01 0F000000 2000 08 00400000 40420F0000000000 32000000`

含义：版本 1，功能位 0x0F，最多 32 个条目，深度 8，缓冲 16384 字节，探针时间 1 000 000 µs，单次访问 50 µs。

#### READ，一个条目

读 `*(uint32_t*)(*(uint32_t*)0x20000008 + 4)`：

条目：`00 0100 04 00000020 01 0800 0400`（ap 0，id 1，size 4，base 0x20000000，n 1，deref_off 8，final_off 4）

请求：`81 01 00 0100 04 00000020 01 0800 0400`

响应（指针读出 0x20001000，该处的值为 0x12345678）：`81 00 01 0100 00 78563412`

指针为 0 时的响应：`81 00 01 0100 30 00000000`

#### WRITE，一个条目

向 0x20000010 写 16 位的 0x1234：

条目：`00 0200 02 10000020 00 0000`，后接值 `3412`

请求：`82 01 00 0200 02 10000020 00 0000 3412`

响应：`82 00 01 0200 00`

#### SUB_SET，两个条目

周期 1000 µs，flags 0，2 个条目：

- 条目 1：id 0x10，size 4，base 0x20000100，n 0，div 1，phase 0：`00 1000 04 00010020 00 0000 0100 0000`
- 条目 2：id 0x11，size 2，base 0x20000104，n 0，div 10，phase 3：`00 1100 02 04010020 00 0000 0A00 0300`

请求：`83 E8030000 00 0200`，后接条目 1、条目 2

响应：`83 00 1100 78000000`（一帧最大 17 字节，估计单帧耗时 120 µs）

条目 2 在 k = 7、17、27… 到期（`(k + 3) % 10 == 0`）。

同样两个条目、周期改为 100 µs 时被拒绝：`83 03 1100 78000000`

还没有 `DAP_Connect` 时：`83 04`

#### SUB_CTRL 开始

请求：`84 01`，响应：`84 00`

#### SUB_READ

响应含两帧：k = 6 只有条目 1 到期，k = 7 两个条目都到期。

0200                       2 帧
